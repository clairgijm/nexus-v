Exigences par tome

Contenu des fichiers d'Exigences importés, rangé par tome dans nexus-v.db. C'est sur ces exigences que porte la vérification.

En bleu : exigences ajoutées ou modifiées à la main ; barrées : supprimées (ignorées par la vérification). Le prochain import du tome écrase ces modifications.

Fiches d'Essai

Exigences testées par les Fiches d'essai chargées (XML de la plateforme par défaut, Excel des autres plateformes), rangées par tome de l'exigence : une ligne par exigence et par test case.

Tables de la base

Le contenu de la base, une table par onglet. Les modifications sont directes et enregistrées tout de suite : seuls les liens entre tables sont contrôlés. Un prochain import ou chargement peut les écraser.

Toute la base (tables et contenu) dans un fichier .sql, à garder en sauvegarde.

STDHL

Exigences citées par les STDHL chargés, avec le test (fiche SYS_) demandé pour chacune : une ligne par exigence et par test (une exigence peut donc revenir plusieurs fois).

Plans d'acceptation

Contenu des Plans d'acceptation chargés, rangés par tome : une ligne par exigence de chaque plan.

En bleu : lignes ajoutées ou modifiées (à la main ou à l'import) ; barrées : supprimées ou ignorées à l'import (sans effet). Elles restent quand le plan est relu ; un nouveau chargement du plan les remplace.

Gestion des fichiers

Chaque fichier chargé est conservé dans fichiers-references/ sous le nom « n°_nom du fichier », et leur liste dans nexus-v.db. Cocher les fichiers à utiliser pour la vérification.

Configuration

Paramètres enregistrés dans config.json ; releases, tomes, plateformes, IADT et MOC, fichiers, exigences et plans gérés dans la base SQL, sauvegardée dans nexus-v.db. Les modifications de tous les onglets sont enregistrées ensemble.

Dossier des fichiers importés

Dossier où NEXUS-V conserve une copie de chaque fichier importé, dans un sous-dossier par type de fichier (nommé dans l'onglet de ce type). Le changement s'applique immédiatement, avec le bouton « Utiliser ce dossier ».

Autres paramètres

Enregistrés avec le bouton « Enregistrer la configuration ». Le port et l'ouverture du navigateur s'appliquent au prochain démarrage du serveur.

Règles IADT / MOC

Pour chaque IADT, les MOC attendus : la ligne doit en avoir au moins un, et aucun autre MOC. Une ligne qui ne respecte pas ces règles est montrée à l'import du plan : l'importer quand même ou l'ignorer. Un IADT sans règle n'est pas contrôlé.
