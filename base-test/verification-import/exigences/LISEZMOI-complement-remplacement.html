Fichiers de complément et de remplacement

Prérequis : les exigences de test exigences/2026-01-01-fct1.xlsx à fct10.xlsx sont chargées dans la base (tomes fct1 à fct10, release A). Chaque fichier part des exigences de la release A de son tome.

  • complement/ : fichiers à importer en complément. Ils ne contiennent que les exigences nouvelles (5 % du tome) et modifiées (5 %). Dans le rapport, regarder la partie « Si le fichier modifie la base ».
  • remplacement/ : fichiers à importer en remplacement. Ils contiennent tout le tome, moins 5 % d'exigences retirées, plus 5 % de nouvelles et 5 % de modifiées. Dans le rapport, regarder la partie « Si le fichier écrase la base ».

Le rapport donne toujours les deux cas : un fichier de complément qui écraserait la base en retirerait les 95 % d'exigences qu'il ne contient pas, ce qu'il doit signaler.

Une exigence modifiée change un seul champ, à tour de rôle : le titre (« — version modifiée » ajouté), le STDHL (« -bis » ajouté) ou la release (A devient B). Une exigence passée en B sort de la release de la base : le rapport la signale dans un groupe hors release A, rejeté à l'import (Rejeté) ; en remplacement, elle est aussi comptée parmi les exigences absentes du fichier. Les exigences nouvelles n'ont pas de ligne de plan : la couverture du plan baisse d'autant.

Le rapport doit donner, pour chaque fichier, les numéros ci-dessous : « exigences nouvelles », « exigences de la base au titre modifié », « exigences de la base au STDHL modifié », le groupe « release B » hors release et, s'il écrase la base, « exigences du tome absentes du fichier » (les retirées et celles passées en B).

Régénérer : python ../../base-test/generateurs/make_verification_modifications.py ../../base-test depuis nexus-v/programme.
